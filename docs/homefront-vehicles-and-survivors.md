# Homefront open-world survivor encounters and first drivable rover

Status: **draft gameplay work on PR #566; NOT deployed as production gameplay**.

## One shared world

The wallet-authenticated Graveyard `homefront-world.json` remains the sole
authority for players, vehicle placement, survivor sites, loot and infected.
Players have different permanent Homefront trailheads but can walk or drive to
the same roads, camps, rescue sites and buildings. Vehicles are not an instance
transition. Guests currently have isolated **temporary** stores and will not
participate in this shared-world state until the safe guest integration in
issue #574.

## Salvage rover vertical slice

One owner-locked **scrap electric rover** per persistent player. A player
physically at their OWN Homefront gate can assemble a vehicle for **24 scrap
and 12 wood** from their refuge stockpile. The server picks a parking space
with clearance for a 1.05m collision radius, never from client-supplied
coordinates. The rover is a muted low-poly welded utility buggy with a cage,
cargo bed, wheels and battered headlamps. The lightweight rendered model
follows server snapshots; other nearby survivors see the same rover.

- **Build:** near your reserved Homefront. In-world E when on the outer
  parking apron, or **B** when within seven metres of your gate.
- **Board:** E next to your own parked rover. Other accounts can see it, but
  not board it without an explicit future invitation/ownership permission.
- **Drive:** WASD or phone steering arrows. The server accepts directional
  controls, validates monotonically increasing input sequences, caps each
  elapsed movement step, sweeps the collision footprint through world geometry,
  and consumes battery charge with distance. Client coordinates are ignored.
- **Park:** E; a collision-safe foot exit must exist. Driver expiry,
  returning to refuge, and party regroup release the seat without erasing the
  physical world vehicle.
- **Recharge:** **C** near a parked rover AT your Homefront garage.
  Costs 2 scrap for 25% battery. No recharge through water, remote inventory,
  free currency, or invented items.
- **Release safety:** the API requires `HOMEFRONT_VEHICLES_ENABLED=1`,
  independently of `HOMEFRONT_CONTINUOUS_MOVEMENT`. The feature stays
  disabled in production until desktop/phone and multiplayer playtests pass.
  Vehicles can't be used to bypass the direct-walking rollout gate.

The current playable prototype map is **only 200m across**, not yet a
DayZ-scale region. The 10 m/s prototype vehicle is useful for proving
handling and collision; a genuine long-distance travel loop needs larger
streamed terrain and infrastructure.

## Density and traversability

`client/arena/homefront-vehicle-corridors.mjs` is the shared reservation
source for drivable space. The city’s 20m block grid retains a 7.6m-wide
road strip where procedural collision debris/trees/wrecks are not spawned.
Dense off-road dressing remains. Pine Crossing logging road and main street
are classified as drivable; narrow creek trails stay on foot. Other authored
solid wrecks and structures still block driving. Both the Three.js scenery
generator and server collision use the same test so hazards match visuals.

This is a first corridor guarantee, not permission to ignore terrain slope,
large trees, bridges, walls, parked wrecks or water. Future vehicle types
will need their own dimensions, slope/traction/road affordances and terrain
partitioning. Keep lanes passable, but preserve cover, derelict cars, fences,
abandoned structures, vegetation, ambient movement, and routes off the main
road so the world does not feel like an empty racing arena.

## Survivors encountered while exploring

Existing `rescue` points already show actual survivor walker models with
roles generated by the established `Core.applyAction(...rescue_survivor)`
system. The direct-walking view now offers a physical **Help stranded
survivor** E prompt within five metres, using the existing authenticated
`/api/homefront/world/rescue` route. The server verifies proximity,
availability, supplies (2 food, 1 ammo), roster caps and shared cooldown,
consumes carried supplies and registers the rescued character in the player's
existing Homefront roster. The new presentation hides giant glowing quest
pillars for living survivor encounters. Existing epic/legendary companion
selection stays linked to the same survivor IDs and rarity rules.

Next survivor pass: wandering scavengers with human AI and line-of-sight,
roaming survivor groups/traders, wounded/ambushed branching conversations,
escort/defense objectives, settlement migration, and threat from other
players. Use one persistent NPC identity/state and shared visibility per
physical encounter, not an artificial NPC spawned separately per player.

## Test and integration gate

- `test/homefront-vehicles.test.js`: assembly cost, anti-theft, path
  validation, sequence/speed limits, dismount, shared visibility and persistence.
- `test/homefront-rover-api-sim.js`: real auth handler, release flag, forged
  payload rejection, shared-car visibility and server-confirmed drive result.
- `test/homefront-rover-corridors.test.mjs`: road/scenery/collision corridor
  parity with off-road density retained.
- `test/homefront-world-sim.js`, `test/homefront-single-overworld.test.js`:
  unique player Homefronts and one shared world.
- `test/homefront-graveyard-3d.test.mjs`: browser wiring to server-authorized
  vehicle actions and physical survivor E rescue interaction.
